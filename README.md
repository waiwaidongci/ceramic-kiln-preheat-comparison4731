# 瓷砖窑炉预热工艺对照

`hxwl-solo2611-4` · 独立样本假设检验

窑炉电表、MES 投入面积台账和冷却后的外观抽检记录按生产批号合并。工艺组对比同一窑线、同一砖种的现行预热和分段预热，判断能否降低单位面积预热电耗，再由质检和窑炉班组决定是否继续限线试行。

## 模拟客户与工作流

澄釉陶瓷佛山厂 · 三条辊道窑，工艺与质检小组共 14 人（模拟）

- 电表读数按班记，MES 按批记，Excel 容易把同一批抄两次
- 预热投入面积不同，直接比总电量会偏向小批
- 汇总缺陷率时平均各批百分比，容易掩盖抽检量差异

烧成工艺组和成品质检组联合审核。节能证据、抽检覆盖、缺陷率绝对上限和相对涨幅均符合并完成试验核对时，由 K02 窑炉班组在 P600 规格继续限线试行，保留现行配方用于回切。

## 业务模块

- 入窑批次台账
- 预热对照台
- 节能与放行判定
- 工艺交接收件箱

## 计算口径

以独立生产批次为观测单位，预热电量除以投入面积后折算到每千平方米，组内各批等权。对现行减分段的平均电耗差做单侧独立两样本 Welch t 检验，以最低节能量为原假设上界，使用各组独立方差和 Welch–Satterthwaite 自由度。小样本要求各组电耗强度近似正态，人工核对批次独立、工况可比和异常批；窑炉余热残留、同一炉次拆分或固定班次安排均可能破坏设计。缺陷率按总缺陷片数除以总抽检片数计算，仅用于现场质量护栏。

电表读数与入窑台账跨系统对账时，在台账中填写电表读数编号；归属存疑的读数用候选批号列圈出可能批次（`|` 分隔），已确认的归属照旧，其余读数与剩余批次一一配齐。所有可行配法都过原节能和质量门槛才可试行，结果页附置信下限最低的配法，同值按批号顺序比较读数编号、取最靠前的一套；无解或超过 4096 种配法时暂缓给出试行结论。读数更正后请导入新台账重新运行，重跑旧分析仍按原读数和候选关系，结论保持一致。

样例输入为 `K02_P600_预热独立批次_2026-11-16至23.csv`，见 `backend/demo/sample.csv`。相同输入与参数复现相同结果。格式错误在导入时提示，样本量或业务约束不满足时在后台运行结果中提示。

## 一班如何使用

1. 07:50（11 月 24 日）工艺员导出 K02_P600_预热独立批次_2026-11-16至23.csv，覆盖 K02 窑线的 31 个 P600 生产批。
2. 08:20 台账员按生产批号核对 MES 面积、预热段电表增量和冷却后外观抽检片数，确认现行 16 批、分段 15 批；交接班存疑的 4 条读数在台账中圈出候选批号，对账 4 种可行配法全部过门槛后才给出试行结论。
3. 09:00 班长翻查预热配方切换记录和工况交接单，核对同一连续投料未拆批，复核窑况或班次未与配方固定绑定。
4. 09:30 工艺员录入已约定的每千平方米节能门槛 20 kWh、单侧 α 0.05 和每组最少 8 批，完成试验核对后运行。
5. 10:10 成品质检组用每组至少 1200 片、分段缺陷率不高于 1.5%、涨幅不超过 0.3 个百分点的规则复核结果。
6. 11:00 烧成工艺组把电耗差的 95% 单侧置信下限与质量护栏明细发给质检和 K02 窑炉班组，工况仍限定为 P600。
7. 14:30 窑炉班长按会签结论登记下一轮限线试行，保留现行配方和异常回切记录。

## 启动与本地开发

```sh
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

停止本地服务可执行 `docker compose down`。仅清理演示数据时使用 `docker compose down -v --remove-orphans`。

浏览器 `http://127.0.0.1:18313`，API `http://127.0.0.1:19313`，数据库宿主端口 `17813`。

前端由 Nginx 提供原生 HTML/CSS/JS，并将 `/api/` 转发给 FastAPI。Python 3.11 Worker 使用 Redis 唤醒和 MySQL 8.0 运行租约，生成的 CSV 由命名卷共享。可编辑 `frontend/src/pages`、`backend/src/services/analysis.py` 和 `backend/demo` 后执行 `docker compose up -d --build --wait`。Compose 默认映射到本机回环地址。更改 `.env` 可配置端口、数据库密码、JWT 密钥以及 `SEED_DEMO` 种子开关。演示凭据适用于本机模拟数据。

| 角色 | 账号 | 密码 | 工作内容 |
|---|---|---|---|
| 主管 | admin | admin-demo-2611 | 查看审计，复核运行，安排与停用分发计划 |
| 分析员 | analyst | analyst-demo-2611 | 导入 CSV、运行计算、下载结果 |
| 只读 | viewer | viewer-demo-2611 | 查看数据、结果和投递回执，下载 CSV |

角色、运行状态和复核状态在 `backend/src/constants/enums.py` 与 `frontend/src/constants/enums.js` 同步定义。角色参与登录、路由授权和工具栏控制。运行状态在 Worker、任务接口和结果页使用。复核状态在运行模型、复核接口和交付页使用。

核心实体为 CSV 数据批次、分析运行、分发计划及其投递回执。业务参数与真实模拟数据位于 `backend/demo/`。后端分为 routes、controllers、services、models、schemas 和中间件，前端分为 api、store、组件和业务页面。授权模式见 [LICENSE](LICENSE)。
